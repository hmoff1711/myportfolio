Selected Infrastructure Work

Cases where the main task was to find the fault boundary, control the change and verify the outcome.

Case 01 · Storage & access control

OneFS SMB permissions for protected media folders

OneFS 9.x · SMB · NTFS-style ACLs · Protocol Audit

Context

A media workflow required users to read, copy and create files in protected folders without being able to modify, delete, rename or change permissions. Other folders had to remain fully writable.

Investigation & change

  • Inspected recursive ownership and ACL data with isi get -DD.
  • Correlated SMB operations with isi_audit_viewer protocol-audit records.
  • Aligned owner, group and inherited ACLs while keeping delete_child away from the protected root.
  • Applied the corrected model through OneFS PermissionRepair.

Validated result

After ACL and ownership normalization, existing objects and tested restricted, full-access and administrative paths behaved according to the access model.

Remaining limitation

New SMB-created files retained an owner privilege that ACL changes alone did not remove. The interim owner-repair control had an approximately one-minute window, node-local scheduling and scan/load considerations; it was not an atomic OneFS-native final solution.

Case 02 · Linux file transfer

ProFTPD SFTP hardening and throughput diagnosis

Ubuntu 24.04 · ProFTPD / mod_sftp · FileZilla · iperf3

Context

SFTP transfers fell to roughly 1.5–3 Mbit/s during business hours but reached 90–97 Mbit/s in the evening. The priority was to separate a server problem from a network-path issue.

Investigation & change

  • Validated mod_sftp loading, host keys, chroot boundaries, setgid directories and Umask 007.
  • Disabled the OpenSSH SFTP subsystem so only ProFTPD handled SFTP sessions.
  • Confirmed that no ProFTPD rate, quota or shaping rule explained the pattern.
  • Compared ports, time windows, iperf3 throughput and RDP behavior.

Validated result

Authentication, uploads and chroot isolation passed validation. iperf3 and RDP degraded in the same daytime window, moving the investigation from ProFTPD to the network path, QoS and provider track.

Remaining limitation

The service audit did not prove a final network or provider root cause; follow-up remained with network-path, QoS and provider investigation.

Case 03 · AD endpoint management

Remote Access Plus HTTPS hardening and GPO pilot

Active Directory · Remote Access Plus · HTTPS/TLS · GPO / SYSVOL

Context

A domain-wide agent rollout needed a secure management path and a verified unattended installer before deployment beyond the pilot group.

Investigation & change

  • Moved web administration to HTTPS 443 and closed the previous management port.
  • Verified the certificate and trust chain from a domain workstation.
  • Confirmed startup-GPO targeting and package availability in SYSVOL on the pilot computer.
  • Held the wider rollout until the vendor setup.bat could be proven unattended.

Validated result

The HTTPS management path, certificate trust and pilot GPO checks passed.

Rollout status

Domain-wide deployment was not completed. The wider rollout remained deliberately gated because the vendor setup.bat had not been proven fully unattended.

Focused resolutions

Two shorter L1/L2 incidents

Windows · SMB · Credential Manager

SMB client reused the wrong saved identity

Clearing mappings, SMB sessions, Kerberos tickets and the Workstation service did not restore the credential prompt. Get-SmbConnection identified the account in use; removing only the affected cmdkey target restored the prompt and isolated the cause from OneFS permissions.

HP MFP · Microsoft 365 · SMTP

Scan-to-email failed before SMTP authentication

Two identical HP LaserJet Enterprise MFP M528 devices were compared against smtp.office365.com:587. The failing device had no DNS server configured, so it could not resolve the SMTP hostname. DNS was corrected without attributing the fault to Microsoft 365 settings; final mail delivery remained a separate validation step.
